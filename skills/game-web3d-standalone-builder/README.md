# game-web3d-standalone-builder

> 沉淀「模块化源码 + 零外部依赖单文件离线 HTML」形态的精品 Web 3D 探索/合成游戏端到端构建、视觉去 Demo 化、多端响应式与触屏无竞态打磨工序。

## 供应链位置

Web 3D 独立游戏生产线 · 工程构建与多端打磨段（M1 玩法策划案 → M2 可离线交付成品）

```
  游戏玩法策划案 / 需求 Prompt ──┐
  存量粗糙 Web 3D 原型工程     ──┼─▶ [game-web3d-standalone-builder] ──▶ 模块化源码仓 (src/ + scripts/)
  实机试玩走查反馈（视觉/多端）──┘                                    └──▶ 零外部请求离线构建包 (dist/*.html)
```

- **上游**：PM / 策划给出的完整关卡与核心循环需求（或已跑通基础逻辑但存在“几何体粗糙像 Demo、开场突兀、新手迷路、手机/小屏 UI 遮挡”的存量 Web 3D 工程）。
- **下游**：产出的 `dist/*.html` 可直接交付本地离线分发、内嵌客户端 WebView 或提交商店/渠道审核；模块化 `src/` 供后续关卡扩展与数值迭代维护。
- **兄弟工序**：`ae-speckit-to-app` 面向原生 iOS + Java 后端商业化应用生成；`ae-review-feedback-visualize` 面向通用界面走查前后对比图制作；本 skill 专注 **Three.js 单文件离线 Web 3D 游戏** 的完整工程实现、程序化美术精雕与双端操控收敛。

## 问题陈述

在让大模型从零构建无外部美术资产的 Web 3D 浏览器游戏时，普遍存在以下 5 个高频痛点：

1. **画面像“粗糙几何体拼搭 Demo”** — 直接拿原生圆柱、圆锥、球体硬拼飞船与山石，缺少 `PMREM` 环境反射导致金属发黑似塑料，缺少法线凹凸与接触阴影导致物体像飘在平涂色块上，或滥用低阈值泛光把整个画面照成刺眼白雾。
2. **开局突兀与新手前期盲从** — 缺少叙事过渡动画，一点开始就弹出满屏任务列表；合成树有多分支共享原矿时不计算全局净缺口，导致玩家在矿区和工坊之间反复跑冤枉路。
3. **玩法平面同质化** — 5 个关卡只是换材料名字加采集数量，缺少通过制造核心装备（如脉冲声呐螺旋钻头、推进能量槽喷气翼）向地下与高空拓展三维探索边界的机制递进。
4. **工坊弹窗割裂 & 中小屏/手机端严重遮挡** — 用全屏毛玻璃黑框遮死 3D 机器，且左右两侧任务面板与状态卡在笔记本分屏、平板、手机横竖屏下占掉一半以上视野。
5. **移动端多指触控竞态与主循环 GC 抖动** — 单布尔值相机拖拽在多指操作（左推摇杆 + 右按喷气 + 第三指转镜头）时互相打断；每帧 `new Vector3/Color` 与高频写 DOM 导致手机端发热掉帧。

## 解决方案

将《星织号（Starweaver）》从初版原型打磨至多端精品版全过程的架构设计、渲染参数、引导算法与防竞态模式固化为 6 阶段可执行门禁：

- **数据驱动与防吞档权威状态机**：全关卡配方/矿脉结构化配置，确定性再生防死锁，合并防抖落盘 + 队列在途产出折算 + `pagehide` 同步屏障。
- **纯程序化 3D 质感四件套**：`PMREMGenerator` 天空环境探针 + `UnrealBloomPass(threshold >= 1.05)` + 环面周期无缝法线贴图（双旋转 UV 防平铺） + 程序化曲线/冲沟雕刻网格（`Lathe` / `Extrude` / 六棱 Fresnel 晶簇）。
- **三维能力锁与 DAG 全局净缺口导航**：开场三幕宽银幕过场无缝移交镜头；中期解锁声呐钻探与能量槽喷气飞行；虚拟库存池递归计算整棵配方 DAG 的共享原料净缺口。
- **空间化全息工坊与侧拉胶囊 HUD**：左半屏实时 3D 机器特写联动 + 右侧多主题斜切全息台；`<= 1240px` 与移动端默认将左右常驻面板收起为边缘迷你胶囊，支持一键「👁 纯净视野」与 4 项非必要提示自由开关。
- **多指 `pointerId` 隔离触控**：`pointer: coarse` 自动浮现虚拟无极摇杆、长按喷气与上下文交互键，支持双指捏合缩放，按 `pointerId` 完全隔离并发触摸流。

## 已放弃方案

### 方案 A: 直接在单个巨型 `.html` 文件中手写全部源码
- **是什么：** 不建 `src/` 模块目录，所有数千行逻辑直接塞在一个 HTML 的 `<script>` 里维护。
- **为什么放弃：** 模块职责耦合极重，后续调优 3D 网格、重构工坊 UI 或审计状态竞态时极易改出回归 Bug；采用 `src/` ES Modules + `esbuild` 0.5 秒内联打包可同时兼顾工程可维护性与单文件离线交付。

### 方案 B: 打开熔炼炉/制造台时弹出居中全屏毛玻璃模态框
- **是什么：** 所有工坊共用一套居中深色背景模糊弹窗，且随身图鉴复用同一套带灰色禁用按钮的列表。
- **为什么放弃：** 试玩反馈“像强行插入的网页表单”，把精心制作的 3D 熔炉火焰与制造台机械臂完全挡死；改为左半屏实时 3D 镜头偏转取景 + 右侧分主题斜切全息终端后，空间沉浸感大幅提升。

### 方案 C: 简单平面距离 `dist2D` 判定所有交互与碰撞
- **是什么：** 角色碰撞与 `[E]` 交互扫描只判断 `(x, z)` 二维平面距离。
- **为什么放弃：** 引入喷气飞行与 `5m~8m` 孤峰高台后，二维判定会导致高空飞过地面熔炉时误弹交互框，以及松开方向键垂直下落时卡进高台侧壁；必须升级为三维高差过滤（`|ry - targetY| <= 2.8m`）与空中无输入水平排斥。

## 构建说明

在含 `package.json` 的游戏目录执行。本仓库该目录是 `starweaver/`，技能与提示词在仓库根目录。需要 Node.js 18 及以上。`three` 与 `esbuild` 只在构建期使用，不进入运行时网络请求。

`esbuild` 的原生二进制按操作系统分发。macOS 对应 `@esbuild/darwin-arm64` 或 `@esbuild/darwin-x64`，Windows x64 对应 `@esbuild/win32-x64`。把某一平台已经装好的 `node_modules` 拷到另一平台后，先在当前系统再执行一次 `npm install`，由 npm 补上当前平台的二进制。lockfile 里的 darwin 与 win32 可选依赖都保留。

产物文件名是 `dist/starweaver-<版本>-<YYYYMMDD-HHmmss>.html`。版本来自工程 `package.json`，时间是构建时的本地时间。页面 `head` 写入同名的 `version` 与 `build-time`。每次构建只保留这一份。可离线双击打开。开发期的 `index.html` 使用 ES Module，请通过本地静态服务打开；交付以 `dist` 单文件为准。不传路径时，离线检查脚本检查这份最新产物。

### macOS

```bash
npm install
npm run build && npm run verify
node ../skills/game-web3d-standalone-builder/scripts/audit-standalone-html.mjs
```

### Windows

在 Windows PowerShell 5.1 中逐条执行。该版本把 `&&` 当作非法语句分隔符。

```powershell
npm install
npm run build
npm run verify
node ../skills/game-web3d-standalone-builder/scripts/audit-standalone-html.mjs
```

若目录里已有从 macOS 拷来的 `node_modules`（只有 `@esbuild/darwin-arm64`），同样先执行 `npm install`。npm 会保留已有的 darwin 包，并安装 `@esbuild/win32-x64`。本机实跑结果见下方「核心链路验证记录 · Windows」。

## FAQ

**Q: 为什么不直接加载压缩后的 `.glb` 外部 3D 模型，而要写 `proceduralMeshes.js`？**
A: 当需求明确要求“零外部模型/图片依赖、单文件离线 HTML 可直接运行”时，纯数学算法生成的雕刻网格仅占几 KB 代码体积即可产生成百上千个高细节顶点；若用户项目允许使用 Blender 导出 `.glb`，可在构建期将 Draco/Meshopt 压缩后的 `.glb` 以 Base64 DataURI 内联进打包脚本，其余渲染管线（PMREM + Bloom + 侧拉 HUD + 多指触控）完全通用。

**Q: 为什么中屏和小屏默认要把左侧任务栏收起成胶囊？新手会不会看不到目标？**
A: 屏幕正上方保留了单行精炼的「下一步指引 + 距离米数」以及机器人脚下的 3D 全息引路箭头（新手无需展开长列表就知道往哪走）；同时左上角 `📋 第X关 (已完成/总数) ▸` 胶囊带实时迷你进度条，想看完整步骤与支线时随时一点即开。

**Q: 为什么标题页转很久再开始，会直接是沙暴或黑夜？**
A: 标题轨道如果调用正式大气更新，会把第 1 关前 150 秒晴天保护提前花掉。标题必须标记为景观预览，不累加游玩计时；「开始任务」和「重置」要清零相位、黑夜和沙暴权重。开场过场若只改天空 uniform、不清这些权重，过场一结束就会弹回沙暴。

**Q: 为什么星夜回荒漠后，船是亮的、倒影却不对，家园草地却很暗？**
A: 三套方向不能各写各的：天空行星、夜间阴影方位、体积光和卤水倒影要共用一个行星向量。阴影仰角可以垫高防拉影，体积光不要跟着垫高后的方向。夜间探针不能靠布尔缓存，过场直接改 `scene.environment` 后缓存会撒谎。家园降落只换天空、不换主光，就会变成亮天空配月光草地。

**Q: 为什么人不再穿翼，镜头还会穿，或者从翼上方看被拉到船头？**
A: 角色碰撞和相机遮挡是两份标记。机翼要同时有限高碰撞和 `occluder`，并写上翼面的下底 `occluderMinY`。弹簧臂若把圆柱当成从地底通到天空，高于机翼的视线也会被挡住。工作台特写如果提前返回，不会做这道求解。

**Q: 卡里斯-4 为什么不做雨雪？**
A: 荒漠设定和现有粒子、声景预算都不接降水。降雪留给以后的冰封星球，不在当前沙漠天气状态机里加第四态。

**Q: `SKILL.md` 和项目里的 `prompts/web3d-spacecraft-game-master-prompt.md` 有什么分工区别？**
A: `SKILL.md` 是给支持 Agent Skills 机制的助手按需自动加载的**通用 Web 3D 构建方法论与质量门禁**（不绑定具体某一款游戏剧情）；而 `prompts/web3d-spacecraft-game-master-prompt.md` 是融合了特定题材设定与全部迭代细节的**完整单次复刻 Prompt**，方便直接粘贴给任何外部对话式大模型独立复现。

## 生命周期

- **填补的 gap：** 填补了“无外部美术资源条件下，如何让 AI 生成的 Web 3D 游戏摆脱简陋几何体 Demo 感，同时一次做好桌面/手机双端适配、防死锁合成链与单文件离线交付”的标准化工程空白。
- **什么会让它过时：** 当浏览器原生 WebGPU 程序化资产库与内置跨端游戏 UI 框架成为行业标配且大模型默认输出即具备 IBL/移动端多指隔离能力时，部分底层样板规则可简化，但关卡防死锁、DAG 净缺口引导与离线纯净度门禁仍长期有效。
